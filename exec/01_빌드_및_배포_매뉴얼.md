# 01. 빌드 및 배포 매뉴얼

> eye-dont-care (S15P11B102) — GitLab 소스 클론 이후 빌드·배포가 가능하도록 정리한 문서입니다.
> 배포 구성: **GitLab + Jenkins CI/CD + Docker(Compose) + Nginx, 단일 EC2**

---

## 1. 시스템 구성 요약

- **서비스 도메인**: `https://eyedontcare.shop` (+ `www.eyedontcare.shop`, `https://i15b102.p.ssafy.io`)
- SSL: Let's Encrypt (Certbot 관리), HTTP(80) 접속은 HTTPS로 301 리다이렉트

```
[사용자 브라우저]
      │ HTTPS (443)                          │ WSS (7443, WebRTC 시그널링)
      ▼                                      ▼
[EC2 호스트 Nginx — SSL 종료, 리버스 프록시]
      │  /         → 127.0.0.1:3102 (frontend 컨테이너)
      │  /api      → 127.0.0.1:8102 (backend 컨테이너)
      │  /ws       → 127.0.0.1:8102 (WebSocket 업그레이드)
      │  /jenkins  → 127.0.0.1:8080 (Jenkins, 같은 EC2)
      │  7443의 /  → 127.0.0.1:7880 (OpenVidu/LiveKit 미디어 서버)
      ▼
[Docker Compose 스택: s15p11b102 (compose.prod.yml)]
  ├─ frontend  : Nginx(정적 서빙) + Vue 3 빌드 산출물  … 호스트 127.0.0.1:3102 → 80
  ├─ backend   : Spring Boot 4.1.0 (JAR)               … 호스트 127.0.0.1:8102 → 8080
  ├─ postgres  : postgres:15-alpine (named volume: postgres-prod-data)
  └─ redis    : redis:7-alpine, AOF on (named volume: redis-prod-data)

[같은 EC2의 추가 Docker 컨테이너]
  ├─ jenkins   : i15b102-jenkins:lts (커스텀 이미지) … 호스트 127.0.0.1:8080 → 8080
  └─ OpenVidu 3.8.0 스택 (single-node 배포)
       openvidu(livekit-server, 로컬 7880), ingress, egress, caddy, meet,
       dashboard, operator, minio, mongo, redis 8.6, 모니터링(grafana/prometheus/loki/alloy)
```

- CI/CD: GitLab 저장소에 push → 웹훅으로 Jenkins 트리거 → `Jenkinsfile` 파이프라인이 EC2 위에서 `docker compose up -d --build` 수행.
- Jenkins는 같은 EC2에서 **Docker 컨테이너**(`i15b102-jenkins:lts`)로 구동되며 `https://eyedontcare.shop/jenkins/`로 접근합니다. 파이프라인이 호스트 Docker를 제어할 수 있도록 Docker 소켓/CLI가 컨테이너에 연결되어 있어야 합니다.
- WebRTC 미디어는 호스트 Nginx가 7443(SSL)에서 받아 OpenVidu(LiveKit) 서버 `127.0.0.1:7880`으로 프록시합니다.
- 모든 컨테이너 포트는 `127.0.0.1`에만 바인딩되므로, 외부 접근은 반드시 호스트 Nginx를 거칩니다.

## 4. 환경 변수 상세

운영 배포 시 환경변수는 **Jenkins Credentials의 Secret file** (`s15p11b102-prod-env`)로 관리하며, `docker compose --env-file "$PROD_ENV_FILE"`로 주입됩니다. `.env` 파일은 Git에 커밋하지 않습니다.

### 4.1 빌드 시점에 번들로 구워지는 값 (프론트엔드 / Vite)

Vite는 빌드 시점에 값을 산출물에 포함하므로, 값 변경 시 **재빌드가 필요**합니다.

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | 선택 (기본 `/api`) | 프론트엔드 HTTP 클라이언트 기본 경로 |
| `VITE_KAKAO_CLIENT_ID` | **운영 필수** | 카카오 REST API 키. 비어 있으면 운영 카카오 로그인 불가 |
| `VITE_KAKAO_REDIRECT_URI` | **운영 필수** | 카카오 로그인 콜백. 백엔드 `KAKAO_REDIRECT_URI`와 **정확히 일치**해야 함 (`https://<도메인>/auth/kakao/callback`) |
| `VITE_SEESO_LICENSE_KEY` | 선택 | SeeSo(Eyedid) 시선추적 SDK 라이선스. 비어 있으면 MediaPipe 시선 추정으로 폴백 |

### 4.2 백엔드 컨테이너 런타임 환경변수

`:?`로 표시된 값이 누락되면 compose 기동 자체가 실패하거나 Spring 컨텍스트 로딩이 실패합니다.

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | **필수** | DB 이름·계정. backend의 `SPRING_DATASOURCE_*`로도 사용됨 |
| `JWT_SECRET_KEY` | **필수** | Base64 인코딩, 디코딩 시 32바이트 이상 |
| `KAKAO_CLIENT_ID` / `KAKAO_CLIENT_SECRET` / `KAKAO_REDIRECT_URI` | **필수** | 카카오 OAuth 서버 측 값 |
| `APP_CORS_ALLOWED_ORIGINS` | **필수** | 서비스 오리진 (예: `https://<도메인>`) — CORS 및 WebSocket 핸드셰이크에 사용 |
| `OPENVIDU_URL` | **필수** | WebRTC 미디어 서버 WSS 주소 — 운영: `wss://i15b102.p.ssafy.io:7443` |
| `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` | **필수** | 미디어 접속 토큰(JWT) 서명 키. OpenVidu 서버 설정값과 일치해야 함 |
| `GMS_API_KEY` | 선택 | SSAFY GMS(OpenAI 호환) 키. 없으면 "눈으로 그리기" AI 채점만 비활성(503/GAME-003), 서비스 기동은 정상 |
| `GMS_BASE_URI` / `GMS_MODEL` | 선택 | 기본값: `https://gms.ssafy.io/gmsapi/api.openai.com/v1/chat/completions` / `gpt-4o` |
| `FRONTEND_HOST_PORT` / `BACKEND_HOST_PORT` | 선택 | 호스트 바인딩 포트 (기본 3102 / 8102) |

자동 주입(compose가 설정): `SPRING_PROFILES_ACTIVE=prod`, `SPRING_DATASOURCE_URL=jdbc:postgresql://postgres:5432/<DB>`, `SPRING_DATA_REDIS_HOST=redis`, `SERVER_PORT=8080`, `SERVER_FORWARD_HEADERS_STRATEGY=native`

## 5. 배포 절차

### 5.1 EC2 사전 준비 (1회)

1. EC2(Ubuntu)에 Docker Engine + Docker Compose v2, Nginx 설치
2. **Jenkins를 Docker 컨테이너로 기동** — 구성 파일은 EC2 `~/jenkins/` 디렉터리 (`Dockerfile`, `compose.yml`)

   `~/jenkins/Dockerfile` — 공식 LTS(JDK 21) 이미지에 Docker CLI·Buildx·Compose 플러그인을 설치한 커스텀 이미지:

   ```dockerfile
   FROM jenkins/jenkins:lts-jdk21

   USER root

   RUN apt-get update \
       && apt-get install -y --no-install-recommends ca-certificates curl \
       && install -m 0755 -d /etc/apt/keyrings \
       && curl -fsSL https://download.docker.com/linux/debian/gpg \
          -o /etc/apt/keyrings/docker.asc \
       && chmod a+r /etc/apt/keyrings/docker.asc \
       && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/debian $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
          > /etc/apt/sources.list.d/docker.list \
       && apt-get update \
       && apt-get install -y --no-install-recommends \
          docker-ce-cli \
          docker-buildx-plugin \
          docker-compose-plugin \
       && rm -rf /var/lib/apt/lists/*

   USER jenkins
   ```

   `~/jenkins/compose.yml` — `/jenkins` prefix로 구동, 호스트 Docker 소켓 공유:

   ```yaml
   services:
     jenkins:
       build:
         context: .
         dockerfile: Dockerfile
       image: i15b102-jenkins:lts
       container_name: jenkins
       restart: unless-stopped

       ports:
         - "127.0.0.1:8080:8080"

       environment:
         JENKINS_OPTS: "--prefix=/jenkins"
         JAVA_OPTS: "-Duser.timezone=Asia/Seoul"

       group_add:
         - "${DOCKER_GID}"

       volumes:
         - /home/ubuntu/jenkins-data:/var/jenkins_home
         - /var/run/docker.sock:/var/run/docker.sock
   ```

   기동 방법 (`DOCKER_GID`는 호스트 docker 그룹 GID):

   ```bash
   cd ~/jenkins
   DOCKER_GID=$(getent group docker | cut -d: -f3) docker compose up -d --build
   ```

   - `JENKINS_OPTS=--prefix=/jenkins`: 호스트 Nginx의 `/jenkins/` 경로 프록시(§7)와 짝을 이룸
   - Jenkins 데이터는 `/home/ubuntu/jenkins-data`에 바인드 마운트로 영속화 (잡 설정·플러그인·Credentials 포함 → 백업 대상)
   - `docker.sock` 마운트 + `group_add`로 파이프라인이 호스트 Docker를 직접 제어
3. **OpenVidu 3.8.0 single-node 배포** (같은 EC2) — livekit 서버(내부 7880), ingress/egress, caddy, minio, mongo 등 컨테이너 일체. 배포 시 생성된 API Key/Secret을 §4의 `LIVEKIT_API_KEY/SECRET`에 사용
4. 보안 그룹: 80/443, 7443(WebRTC 시그널링), WebRTC 미디어 UDP 포트 범위 개방
5. 호스트 Nginx 리버스 프록시 설정 (§7) 및 SSL 인증서 발급 (Certbot / Let's Encrypt)

### 5.3 자동 배포 (평상시)

**`main` 브랜치에 push(MR 머지 포함)** 되면 GitLab 웹훅이 Jenkins 잡 `s15p11b102-prod`를 트리거하고, 파이프라인이 자동으로 다음을 수행합니다.

## 6. 배포 시 특이사항

1. **DB 스키마는 마이그레이션 도구 없이 Hibernate `ddl-auto: update`로 생성·갱신**됩니다. 첫 기동 시 자동으로 테이블이 만들어지고, `data.sql`이 게임 카탈로그(games)를 멱등하게 시드합니다(`WHERE NOT EXISTS`). 별도 DDL 실행이 필요 없습니다.
   - 예외: `schema.sql`이 `users.profile_img_code` CHECK 제약을 갱신합니다(자동 실행).
2. **Vite 환경변수는 빌드 시점에 굽습니다.** 카카오 키·리다이렉트 URI·SeeSo 키 변경 시 프론트엔드 이미지 재빌드(재배포)가 필요합니다.
3. **카카오 redirect URI 3중 일치**: 프론트 `VITE_KAKAO_REDIRECT_URI` = 백엔드 `KAKAO_REDIRECT_URI` = 카카오 개발자 콘솔 등록값. 하나라도 다르면 로그인 실패.
4. **호스트 Nginx의 `/api` `proxy_read_timeout`을 120s 이상으로 설정**해야 합니다. "눈으로 그리기" AI 채점(gpt-4o Vision)이 수십 초 걸릴 수 있어, 기본 60초면 502가 발생합니다.
   ⚠️ **WARNING — 현재 EC2 운영 설정에는 이 값이 미설정(기본 60s) 상태입니다** (§7의 `/api/` 블록 참고). AI 채점이 60초를 넘기면 502가 발생할 수 있으므로 `proxy_read_timeout 120s;` 추가를 권장합니다. 컨테이너 내부 Nginx(`frontend/nginx.conf`)와 백엔드 GMS read-timeout(60s)은 이미 반영되어 있습니다.
5. **COOP/COEP 헤더 유지**: 프론트 컨테이너 Nginx가 `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`를 내려줍니다. MediaPipe 스레드 WASM(SharedArrayBuffer)에 필수이며, 호스트 Nginx가 이 헤더를 제거하면 눈 추적 카메라가 조용히 실패합니다.
6. **웹캠 권한은 HTTPS(또는 localhost)에서만** 허용되므로 운영 도메인은 반드시 HTTPS여야 합니다.
7. **WebSocket 경로**(`/ws/match`, `/ws/waiting-rooms/{roomId}`)는 호스트 Nginx에서 `Upgrade`/`Connection` 헤더 전달 + 긴 `proxy_read_timeout`(3600s)이 필요합니다.
8. **데이터 보존**: postgres/redis 데이터는 named volume(`postgres-prod-data`, `redis-prod-data`)에 저장됩니다. `docker compose down -v`는 데이터를 삭제하므로 운영에서 금지.
9. Jenkins `disableConcurrentBuilds()`로 동시 배포가 방지되어 있습니다.
10. `GMS_API_KEY` 없이도 서비스는 기동하지만 "눈으로 그리기" 그림 인식만 비활성화됩니다.

## 7. 호스트 Nginx 설정 (EC2 실제 운영 설정)

- 설정 파일 위치: `/etc/nginx/sites-available/` (→ `sites-enabled/`로 활성화), 전역 설정은 `/etc/nginx/nginx.conf` (Ubuntu 기본값)
- SSL 인증서: Let's Encrypt / Certbot 관리 (`/etc/letsencrypt/live/eyedontcare.shop/`, `/etc/letsencrypt/live/i15b102.p.ssafy.io/`)
- 전체 유효 설정 확인: `sudo nginx -T`

        proxy_set_header Host $host;

    location / {
