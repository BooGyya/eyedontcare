# Social Accounts 운영 DDL

카카오 로그인 배포 전에 운영 PostgreSQL에 한 번 적용합니다.
운영 DB를 백업한 뒤 애플리케이션보다 먼저 배포해야 합니다.

## 적용

```sql
CREATE TABLE social_accounts (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id BIGINT NOT NULL,
    provider VARCHAR(20) NOT NULL,
    provider_user_id VARCHAR(255) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL,

    CONSTRAINT fk_social_accounts_user
        FOREIGN KEY (user_id)
        REFERENCES users (id),

    CONSTRAINT uk_social_accounts_user
        UNIQUE (user_id),

    CONSTRAINT uk_social_accounts_provider_identity
        UNIQUE (provider, provider_user_id)
);
```

개발 환경에서 Hibernate `ddl-auto: update`로 이미 생성된 경우
동일 DDL을 다시 실행하지 않습니다.

## 확인

```sql
SELECT
    column_name,
    data_type,
    is_nullable,
    character_maximum_length
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'social_accounts'
ORDER BY ordinal_position;
```

```sql
SELECT
    constraint_name,
    constraint_type
FROM information_schema.table_constraints
WHERE table_schema = 'public'
  AND table_name = 'social_accounts'
ORDER BY constraint_name;
```

DDL 적용 후 `prod` 프로필로 애플리케이션을 기동해 Hibernate
`ddl-auto: validate`가 통과하는지 확인합니다.

## 롤백

애플리케이션을 이전 버전으로 되돌린 후 실행합니다.

```sql
DROP TABLE social_accounts;
```
